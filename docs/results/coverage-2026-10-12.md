# Answer coverage check (2026-10-12)

**In plain terms:** Weir's grounding check confirms that an answer's words come from the source. It can't see what the answer leaves out. The coverage check closes that gap for hard details:
- **The rule:** if a question asks *when*, *how much*, *which extension* or *how long*, the answer must contain a time, a price, an extension or a quantity that the matching source line gives.
- **If it doesn't:** the small model's answer goes to the large model instead.

With the check on, the router's strict "no worse answer" bar allows a much looser setting. Offline the router alone saves about 37%, against 6% before; live, full Weir answered a cold pass **45% cheaper** than the same-day baseline with identical quality.

**Background:**
- **Design:** [`specs/2026-10-12-answer-coverage-check-design.md`](../superpowers/specs/2026-10-12-answer-coverage-check-design.md); decisions D79 (the check) and D80 (the router setting).
- **Code:** `services/weir/src/weir/router/coverage.py`.
- **Why it was needed:** D78. Once q-154 turned out to be a labelling gap, the only answer the looser setting made worse was q-036. The small model said "the first Saturday of every month" and left out "10 am to 3 pm".

## 1. Offline: the check on saved answers (no model calls)

`weir_eval coverage` re-fetched each question's chunks from hospital-rag (retrieval only, stub mode) and ran the check on the saved answers of:
- the small-model trial (`eval/reports/20261004T171944Z-small_only-all/`)
- baseline v3, the large model (`eval/reports/baseline-v3/`)

| | Small model (gpt-oss-20b) | Large model (gpt-oss-120b) |
| :-- | --: | --: |
| Answers checked | 158 | 158 |
| Flagged | **1 (q-036)** | 0 |
| Good answers (judge 5, full facts) flagged | **0 of 153** | 0 of 153 |
| Synthetic omissions caught | **102 of 102** | 103 of 103 |
| The stricter "every detail" variant: good answers flagged | 24.8% | 25.5% |

**Synthetic omissions.** Every good answer that passed was copied once per detail type the question asked for and the answer gave, with every detail of that type deleted. The small set covers money 58, time 25, quantity 9, day 5 and extension 5.

**Refusals are skipped.** "Sorry, I couldn't find that..." appears on 14 small-model answers. Grounding already escalates every refusal, and live, a refusal cites nothing, so the check has nothing to read. Before the skip, two correct refusals to unanswerable questions (q-136, q-139) counted as false flags.

**What the check can judge.**
- **Asks for a detail:** 120 of the 158 questions ask for at least one detail type:

  | Detail type asked for | Questions |
  | :-- | --: |
  | money only | 62 |
  | time only | 25 |
  | time and day | 12 |
  | quantity only | 9 |
  | other combinations | 12 |

- **Not judged by design:** the other 38 ("which", "where", "what is"). The check passes them unread.
- **Read in practice:** of the 113 detail-asking questions the small model actually answered (not refusals), the line the check reads contains a required detail for **97**. For the other **16 (14%)** the best-matching line holds no such detail, so they pass unread:
  - a table's header row ("| Package | Price |") wins over the data row (q-007, q-071)
  - a two-part question matches the other part (q-088, q-100, q-144, q-146, q-149)
  - the question's wording differs from the source line holding the detail (for example "discharge timing", "night shift start")

**A bug the final review found.** The first version read about a third of these questions unread. hospital-rag starts every chunk with a "Title: Heading" line. That line carries the question's topic words but no details, so it often won the best-match contest on its own (for example "ICU visiting hours: Visiting windows"). The heading is now never a candidate; each line under it borrows the heading's words instead. That fix cut the unread questions from 36 to 16. It changed no flag on the saved answers (still only q-036, still 0 false flags), and the synthetic set grew from 84 to 102 because more real detail lines are now read.

**Type coverage, not every detail.** The check asks for *one* detail of each type the question needs. A morning-only question answered with the morning time passes. Requiring every detail on the matching line would wrongly flag about a quarter of good answers.

## 2. Offline: the router with the check

`weir_eval simulate --coverage` replays both models' answers over the same 5,400 router settings. A small answer now counts as acceptable only if it passes grounding *and* coverage; otherwise it escalates, costing the small call plus the large one. The bar is unchanged: the strict D33 bar, no visible quality loss.

| :-- | --: | --: |

| Cost saving vs always large, tune | 7% | **39.2%** |
| Cost saving, holdout | 5% | **33.5%** |
| Cost saving, all 158 | 6% | **37.5%** |
| Questions routed small | 13% | 77% |
| Escalated (of small-routed) | 0% | 2% (q-036 by coverage; q-138, q-150 refusals by grounding) |
| Judge / facts vs the baseline, all | 4.91 / 0.981 = 4.91 / 0.981 | 4.91 / 0.981 = 4.91 / 0.981 |

**Reports:**
- `eval/reports/simulate-20261012T143847Z/` (type coverage, chosen)
- `eval/reports/simulate-20261012T143850Z/` (the "every detail" variant: saves 25.0%, with 19% of small answers escalated)

**Settings left as they were:**
- `low_confidence` stays 0.50.
- `grounding.min_overlap` stays 0.3 (D39). The simulation's tie-break picked 0.5, but 0.3–0.6 route identically here, and 0.3 keeps good large answers cacheable.

**The gate passed on every check:**
- no errors
- lower cost
- judge within 0.1
- facts no lower
- the small route no worse
- 0 wrong cache hits

**No single question scored differently from the baseline, in judge or in facts.**

**q-036 behaved as designed:**
1. It routed small.
2. The check flagged it (`missing:time`).
3. It escalated, and the large model's full answer ("the first Saturday of every month ... from 10 am to 3 pm") scored 5.

Weir's request log and `/metrics` agree: `weir_coverage_failures_total` read small 1, large 0.

**The live result holds for the fixed check.** The live run used the check before the heading fix. Re-scored with the fixed check, none of the run's returned answers is flagged, so the same requests would have escalated, at the same cost.

## Caveats

- **The offline scorer reads slightly different text from live Weir.** Offline, the check reads every re-retrieved chunk from the documents the saved answer cited; live, only the exact chunks it cited. Passages can differ.
- **One real omission.** Only one real omission exists in the 158 answers; the 84 synthetic ones show the rule works by construction, not that it covers every way a model can leave something out. A missing instruction ("bring ID proof") or a wrong-but-present detail is not caught.
- **Rules from this knowledge base.** The detail patterns and question triggers come from this hospital's FAQ (₹ prices, "ext." numbers, am/pm times). Another domain would need its own.
- **Tuned on the same 158 questions.** The router thresholds were tuned on these questions; the holdout split (48) is the independent check, and the live run is the real one.
